2-1. 지금의 제품 정의 (2026-11-18 저녁 사용자 결정. 아래 옛 설명과 다르면 이쪽이 맞다)

- 하는 일은 네 가지뿐이다: 매일 뉴스 2건 선별, 날짜별 목표 달성 기록(달력), 주간 리뷰, 연속 기록.
- 분류, 주제 이름, 이슈 묶음(실), 추적 지표, 후속 점검은 모두 없앴다. 다시 만들지 않는다.
- 탭은 셋: 오늘 / 기록 / 주간 리뷰. 이슈 탭(src/screens/Threads.tsx)은 삭제했다.
- 하루 목표: 그날(한국 시각) 안에 그날 기사 2건을 모두 읽기.
  상태는 달성, 늦게 읽음(날짜가 지난 뒤 읽음), 미달성, 오늘 남음. 계산은 src/store.tsx 의 dayStatus.
  기록은 user.daily[날짜] = { total, read, doneAt } 로 읽은 기록과 함께 저장한다.
- 연속 기록: 연달아 달성한 발행일 수. 주말처럼 발행이 없는 날은 세지도 끊지도 않는다. 늦게 읽은 날은 끊긴다.
  오늘 화면 맨 위에 연속 일수, 이번 주 월~금 표식, 오늘 할 일 한 줄을 둔다. 목표를 채우는 순간 달성 화면이 뜬다.
- 주간 리뷰: 이번 주 달성 현황, 이번 주 기사 다시 보기, 금요일에 발행되는 다섯 문항 퀴즈.
- 앱 아이콘 교체는 보류 중이다 (시안 여섯 개는 디자인 캔버스에 있다).
- 기사 선정 기준(같은 날 추가 결정): 그날의 주가 등락이나 분기 실적이 아니라 자본시장의 구조를 다룬다.
  제도와 규칙의 변화, 지배권과 소유 구조의 변화, 주주 권리와 자본 배분, 시장 구조, 해외의 같은 유형.
  사용자가 든 사례는 방향을 보여 주는 예일 뿐이다. 지시문에 특정 사건 이름을 적지 않고 유형과 판단 질문으로 유도한다.
  가능하면 1건은 국내, 1건은 해외. 전문은 ops/daily-task-prompt.md 2단계.
- 해외 매체 접근의 실제 사정 (2026-11-18 확인):
  이 계정의 기본 환경에서는 해외 매체 주소가 모두 막혀 있다. 세션에서 환경을 만들거나 고치는 요청은 서비스가 거절했다.
  검색 도구(WebSearch)는 되지만 wsj.com, ft.com, reuters.com, apnews.com, bbc.com, nytimes.com, theguardian.com, economist.com 은
  검색 도구가 접근하지 못하는 도메인이다. bloomberg.com, asia.nikkei.com, cnbc.com, 국내 영문 매체는 검색이 된다.
  그래서 지금 해외 건은 검색으로 찾고, 열람 가능한 보도에서 내용을 확인한 것만 싣는다.
  사용자가 환경 설정의 허용 도메인에 해외 매체 RSS 주소를 넣으면 지시문이 그 RSS 를 먼저 쓴다(막혀 있으면 건너뛰게 써 두었다).
  월스트리트저널과 파이낸셜타임스는 유료라 RSS 가 열려도 제목과 공개 요약까지만 볼 수 있다. 유료 벽은 우회하지 않는다.

2-2. 통합 앱 (2026-11-19 사용자 결정. 2-1 보다 뒤의 결정이라 다르면 이쪽이 맞다)

- 한 앱에서 세 가지를 한다: 뉴스 읽기, 영단어, Latticework(여러 분야의 개념을 문제로 복습).
  앱 이름은 "Latticework". 개념마다 앱을 따로 만들지 않는다.
- 화면 구조: 홈에 세 과제(뉴스, 영단어, Latticework)가 줄로 나오고, 누르면 그 과제 화면으로 들어간다.
  탭은 홈 / 기록 / 지식 (2026-11-20 부터. 예전 리뷰 탭과 Review.tsx 는 없앴다. 자세한 것은 2-3).
  디자인은 Toss 식(src/theme.tsx 의 색과 글자 크기, src/ui.tsx 의 부품). 예전 "지면형"과 종이 결은 쓰지 않는다.
- 하루 목표: 그날 있는 과제를 그날 안에 모두 끝내기. 뉴스는 발행된 날에만, 영단어와 Latticework 는 매일(주말 포함).
  연속 기록은 하나로 센다. 계산은 src/store.tsx 의 partsOf, statusFromParts, useGoals.
- 복습 자료: docs/data/study.json (개념 42, 문제 210, 영어 표현 95. 2026-11-19 에 복습 프로토타입
  https://claude.ai/artifact/VgqA21FmAHVCFLKn9tTofY 의 저장소와 단어장 시트 두 개에서 옮겼다). 공개 저장소에 올리는 것을 사용자가 허락했다.
  단어장 시트: 금융영어 1_aCB-bvYSdlwxiS9Y0Cw91NiCaPTuXD7FN0gEeUiReA, 일반회화 1P9fT2CUHIPzHu_0iYsbgCGY1ev-JpX5CiGT4-kM4D5U
- 출제와 기억 계산: src/study.ts. 항목(개념 하나, 표현 하나)마다 난이도와 안정성을 두고 기억 확률이 90% 아래로

  Latticework 는 하루 5문제(복습할 개념 먼저, 새 개념은 하루 3개까지), 영단어는 복습 10개 이내와 새 표현 5개.
  첫 오답은 힌트만 주고 한 번 더, 두 번째 오답은 정답을 보여 주고 세션 끝에 다시 낸다. 설명 문제는 스스로 채점한다.

- 문제의 품질 기준 (2026-11-19 사용자 지적으로 정함. 문제를 새로 만들거나 고칠 때 반드시 지킨다):
  문제만 읽고도 무엇을 묻는지 정확히 알 수 있어야 한다. 등장하는 대상, 기호, 약어는 문제 안에서 소개한다.
  강의, 교수, 수업, 강의자료, 도표 번호, 예제 번호, 단원처럼 출처를 가리키는 말을 쓰지 않는다. 사실만 적는다.
  아래첨자와 위첨자는 <sub>, <sup> 태그만 쓴다(화면이 이 둘만 그린다). 다른 태그, LaTeX, HTML 엔티티는 쓰지 않는다.
  계산은 암산 수준. 힌트는 답을 말하지 않는다. 해설은 왜 그 답인지 문제만 본 사람도 이해하게 쓴다.
  같은 날 같은 문제는 다시 내지 않는다(틀린 문제만 세션 끝에 한 번). 추가 학습은 오늘 안 나온 항목부터 고른다.
- 내지 않는 문제 유형 (2026-11-19 사용자 결정): 자기 말로 설명하기(스스로 채점), 영단어의 격식 고르기, 우리말에서 영어 떠올리기.
  남은 유형: Latticework 는 인식, 특징, 구분, 적용. 영단어는 뜻 고르기, 정의에 맞는 표현, 빈칸.
- 이 앱의 목적 (사용자 표현): 살면서 배운 지식을 장기 기억으로 유지하고 서로 연결해 사고 역량을 키우는 도구. 시험 대비가 아니다.
  시험 범위, 수업 진도 같은 기준으로 문제를 만들지 않는다.
- 영단어 단어장은 셋이다: 토익 어휘 160(단어 위주, 2026-11-19 추가. 시트에는 아직 없고 study.json 에만 있다),

- 복습은 자체 주소 빌드에서만 된다. Claude 링크용 빌드는 뉴스만 보인다.

2-3. 지식 탭, 해금, 돌아보기, Latti (2026-11-20 사용자 결정. 2-2 보다 뒤라 다르면 이쪽이 맞다)

- 탭은 홈 / 기록 / 지식. 리뷰 탭은 없앴다. 주간 종합 퀴즈는 지식 탭 뉴스 칸의 주 머리와 돌아보기 뉴스 카드에서 연다.
- 지식 탭은 나눔 단추 세 칸이다. Latticework(배운 개념의 지도. 마디를 누르면 개념 시트: 반복 횟수, 기억 확률, 다음 복습, 복습하기),
  뉴스(읽은 기사를 주별로. 주 머리에 주간 종합 퀴즈), 단어장(전체 / 단어 / 구문 칩과 낱말 카드).
  뉴스 칸에는 기억 상태가 없다. 뉴스와 단어장 칸은 지식 탭을 연 뒤 한가할 때 숨긴 채 미리 그려 둔다.
- 분류: 학문 / 분과 / 주제(없을 수 있다) / 개념. docs/data/study.json 의 nodes 에 지금 앱에 있는 마디만 둔다
  (id 'n:...', ko, short, en, rank, parent, 학문에만 color 와 domain). 개념마다 node 에 달린 마디 id 가 있다.
  전체 분류 목록(motion-lab/v8/taxonomy.json)은 Claude 가 문제를 만들 때 보는 안내서이고 앱에는 넣지 않는다.
- 배운 날 규칙(소유자 결정): 개념은 처음 답한 날(card.first, 한국 날짜)부터 배운 것이다. 자료에 넣은 날은 쓰지 않는다.
  학문과 분과는 그 아래 개념이 처음 풀린 날에 생기고, 주제는 그 아래 개념이 3개째 풀린 날에 생긴다(그 전까지 개념은 분과에 바로 달린다).
  계산은 기기 안에서 한다: src/knowledge.ts (learnedTree, unlockEvents, unlockPlan, freshSince).
- 개인 기록에 더한 것(src/types.ts, 동기화된다): newsLog(읽은 기사 제목, 날짜, 주소. 기사 묶음에서 빠져도 목록이 남는다),
  scores(퀴즈 점수), seen(본 해금 unlocks, 본 돌아보기 recaps, 지도를 본 날 map 과 그때 이미 있던 그날 것 mapIds.
  같은 날 지도를 본 뒤에 배운 개념도 반짝이게 한다). Claude 링크 빌드에서는 seen 이 문서
  data/users/{본인}/seen 에 저장된다. 내보내기는 version 3, 가져오기는 2 와 3 을 받는다.
- Latti: docs/data/latti.json(늘 쓰는 줄 bank 와 하루 묶음 목록 daily). 고르는 규칙은 src/lattiLines.ts, 표식과 말풍선은 src/latti.tsx,
  모양은 src/lattiTypes.ts. 자체 주소 빌드만 받는다(Claude 링크 빌드는 src/cheer.ts 의 문장을 쓴다).
  한 화면에 한 줄, 기사를 읽는 동안에는 말하지 않는다. 표식은 지금 앱 아이콘이다(LattiAvatar 하나만 바꾸면 된다).
  고르는 순서: 상황(s)과 조건(when)이 맞는 줄 가운데 우선 단계(p)가 높은 것, 3일 안에 보인 줄은 피한다, 하루 묶음 줄은 무게 3배.
  기사가 없는 날에 기사를 말하는 줄은 when 에 "newsToday": ">=1" 을 붙인다.
- Latti 하루 묶음은 아침 작업이 날마다 daily 목록 끝에 하나 덧붙인다(같은 date 의 묶음이 있으면 그것을 바꾼다).
  bank, rules, persona 는 건드리지 않는다. 14일 지난 묶음은 지운다. 아침 발행 작업은 저장소에 닿지 못하므로
  묶음을 만들어 두고, 동기화 세션이 feed.json 과 함께 docs/data/latti.json 에 덧붙여 main 에 커밋하는 식으로 잇는다.
  이 연결은 아직 만들지 않았다(지시문 ops/daily-task-prompt.md 와 예약 작업 둘 다 그대로다). 지금 daily 에는 2026-11-20 묶음 하나만 있다.
  묶음 하나의 모양:
    { "date": "2026-11-21",            // 이 날부터 쓴다(한국 날짜)
      "by": "morning-job",
      "until": "2026-11-23",           // 선택. 쓸 수 있는 마지막 날. 없으면 date 하루만. 금요일 묶음은 월요일까지로 두면 주말에도 쓴다
      "lines": [
        { "id": "d1121.01",            // 묶음 안과 bank 와 겹치지 않게. d{MMDD}.{두 자리}
          "s": "greet",                // 상황 열쇠 하나 또는 목록. latti.json 의 situations 에 있는 것만
          "t": "어제 배운 WACC로 오늘 기사를 따져 볼까요?",   // 해요체, 40자 안, 두 문장까지, 실제 이름과 숫자만
          "when": { "part": "morning", "newsToday": ">=1" }, // 선택. "값", ">=n", "a..b", "a|b"(또는), true/false (src/lattiLines.ts 의 test)
          "p": 1,                      // 선택. 우선 단계
          "w": 1,                      // 선택. 무게
          "until": "2026-11-21" } ] }  // 선택. 줄마다 따로 끝나는 날
  쓰기 전 검사: 줄마다 src/lattiLines.ts 의 lint 가 빈 목록이어야 한다(금지어, 긴 줄표, 화살표, 화면 설명, 죄책감, 부풀림, 길이).
  예전 모양(최상위 today 에 묶음 하나)도 앱이 계속 읽는다.
- 시작 화면 다음의 차례(src/screens/Flow.tsx 의 AfterSplash). 앱을 열 때 한 번만 정한다. 자료가 3.5초 안에 준비되지 않으면 이번에는 띄우지 않는다.

고치는 순서:
  1) 소스 수정
  2) npx tsc --noEmit
  3) npm run build:web
  4) node scripts/shots.mjs light   (dark 도 가능. shots/ 폴더에 그림이 남는다), node scripts/shots-site.mjs
  5) Artifact 도구로 out/index.html 을 게시하고 files 에 {"app.js": "out/app.js"} 를 넘긴다.
     다른 세션에서는 url 에 앱 링크를 넣어야 같은 주소가 유지된다. capabilities 는 생략하면 그대로 이어진다.

설계에서 지킨 규칙:
- 화면은 React Native 기본 컴포넌트와 react-native-svg 만 쓴다. 웹 전용 코드는 Platform.OS === 'web' 분기 안에만 둔다.
- 화면에 읽는 법을 설명하지 않는다(범례, 안내 문장, 상태 문장 없음). 우리말, 긴 줄표와 화살표 없음, "더 풀기" 대신 "추가 학습".
- 내비게이션은 Expo Router 대신 상태 기반으로 했다. 게시된 페이지는 주소 경로를 바꿀 수 없기 때문이다.
- 바깥 링크는 웹에서 진짜 링크(href)로 그린다. window.open 은 막힌다.
- 한글 줄바꿈은 낱말 단위(word-break: keep-all)로 한다.

5. 데이터 구조 (앱 링크에 딸린 문서 저장소)

공용 문서 (예약 작업이 쓴다. Claude 세션에서는 ArtifactData 도구로 읽고 쓴다)
- days/{YYYY-MM-DD}      { date, articles: [기사 2건], followups: [추적 지표 점검 결과], note }
- threads/{영문-id}      { id, name, startedAt, status, indicator, entries: [...], nextCheck, updatedAt }
- reviews/{YYYY-Www}     { id, title, range, questions: [5문항], threadSummary }   금요일에 생성

기사 한 건의 필드:
  id, date, category("대분류 · 주제"), title, gist, source, url, publishedAt, minutes,

  links[{kind: continue|reverse|cross|pattern|new, refDate, refArticleId, refTitle, text}],
  lattice {models[], text}, counter, trackers[], checkDate, glossary[{term,def}],
  threadId, threadName, threadOrder, isNewThread
  점검이 끝난 과거 기사에는 checked { date, verdict } 가 붙는다.

개인 문서 (앱이 쓴다. 세션에서는 collection "data/users/me" 로 읽는다)
- progress   { read: { 기사id: 읽은 시각 } }
- memos      { memos: { 기사id: { text, updatedAt } } }
- settings   { market: kr | both | us }
- quiz       { answers: { 복습id: { 문항번호: 고른 보기 } } }

7. 알아 둘 제약 (실제로 부딪힌 것)
====================================================================
- 게시된 페이지는 잠긴 틀 안에서 뜬다. 서비스 워커, 웹 푸시, 주소 경로 변경이 안 된다.
  그래서 알림은 예약 작업의 Claude 앱 푸시로 대신했다. 알림 시각은 작업이 끝나는 때라 몇 분 오차가 있다.
- 예약 작업은 커넥터를 물려받지 못했다(이 계정에서는 connectors 지정이 거절됨).
  그래서 예약 실행은 구글 드라이브에 쓰지 못한다. 드라이브 문서는 드라이브가 연결된 대화에서 채워야 하거나,
  사용자가 claude.ai 의 예약 작업 화면에서 이 작업에 Google Drive 커넥터를 붙여야 한다.
- 드라이브 커넥터는 새 파일 만들기만 된다. 2026-11-19 부터 이 대화에는 Google Docs 커넥터도 붙어 있어
  기존 문서를 그 자리에서 고칠 수 있다(read_doc, update_doc. 링크가 그대로 남는다). 고칠 때는 지우고 다시 만들지 말고 이것을 쓴다.
  예약 작업 세션에는 커넥터가 없고, 동기화 세션에 Docs 커넥터가 붙어 있는지는 확인하지 않았다.
  연결의 기준 장부는 여전히 앱 데이터베이스다.
- Expo 문서 사이트와 expo install 이 쓰는 호스트가 막혀 있다. 패키지 버전은
  node_modules/expo/bundledNativeModules.json 을 보고 npm install 로 넣는다.
- GitHub 계정(Dodd313)은 연결돼 있다. 저장소 만들기와 저장소 설정 변경은 세션에서 막혀 있다.
- 예약 실행 한 번이 사용량을 적지 않게 쓴다. 주간 사용량이 한도에 닿으면 그날 실행이 실패할 수 있다.
- 드라이브 문서는 scripts/day-to-html.mjs 로 만든다. days 문서를 ArtifactData 로 받아(out_dir 지정)
  node scripts/day-to-html.mjs <받은 json> 의 출력 HTML 을 create_file(contentMimeType text/html)로 올린다.
